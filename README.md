SPRING - SECURITY

Spring JWT is not a standalone product, but rather the integration of JSON Web Tokens (JWT) within the Spring Security framework to handle secure, stateless user authentication and authorization.
1. Authentication (The Handshake)The client (e.g., a React app or mobile app) sends the user's credentials (username and password) to the server via a secure POST request.2. Token Creation & IssuanceThe server verifies the credentials against a database. If they are valid, the server creates a JWT.The server adds specific data inside the token (like the user_id and their roles).The server signs the token using a secret key (symmetric) or a private/public key pair (asymmetric).The server sends this token back to the client.3. Sending the TokenThe client receives the token and stores it (usually in localStorage, sessionStorage, or a secure cookie).For every subsequent request to a protected route, the client attaches the JWT inside the Authorization header using the Bearer schema:httpAuthorization: Bearer <your_jwt_token_here>
Use code with caution.4. Verification (Stateless Processing)When the server receives the API request, it intercepts the header and inspects the token.Signature Check: The server applies its secret key to verify that the token hasn't been altered by a third party.Expiration & Claims Check: The server checks if the token is expired (exp) and extracts the user data directly from it.If the token is valid, the server processes the request and returns the data. The server does not need to query a session database, making the transaction completely stateless.Anatomy of a JWTA JWT is a single string split into three distinct parts, separated by dots (.): Header.Payload.SignaturePartComponentDescriptionExample (Decoded)1. HeaderAlgorithm & TypeSpecifies the token type (JWT) and the signing algorithm being used (e.g., HS256).{"alg": "HS256", "typ": "JWT"}2. PayloadThe ClaimsContains the actual data being transmitted, such as user info and token expiration.{"sub": "1234567890", "name": "John Doe", "role": "admin", "exp": 1782349000}3. SignatureSecurity CheckFormed by hashing the encoded header, encoded payload, and a secret key known only to the server.Ensures the token was not tampered with.Note: The Header and Payload are just Base64Url encoded strings. They are obscured, not encrypted. Anyone can decode them, so you must never put sensitive secrets (like raw passwords) inside the payload.
